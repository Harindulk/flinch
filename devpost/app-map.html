Flinch: app map

A snapshot of how the code fits together, from commit 24bb579 (26 Oct 2026). It can drift as the code changes.

What it is, in one breath

A single web page with no server. Chrome records the game window and the webcam as two files. A background worker reads the tester's face about 15 times a second. Our code turns those readings into a frustration score and a delight score, measured against the tester's own resting face. After Stop, it pins the biggest reactions so you can replay them.

One action, followed through the code

The tester grins at a jump; a green pin appears on Review.

1. The face is read

src/face.worker.ts, the self.onmessage handler: MediaPipe's Face Landmarker turns each camera frame into blendshape scores (such as mouthSmileLeft) and posts them back. src/face.ts › FaceReader.start hands the camera to the worker.

2. Scores against this tester's resting face

src/signals.ts › rawSignals mixes the blendshapes into frustration and delight. Scorer.push says how many "spreads" above rest they are. The rest level comes from the ten-second calibration (calibrate) and drifts slowly during play. Each result becomes a sample in src/screens/record.ts › onFace.

3. Pinned and replayed

On Stop, record.ts › finish calls src/moments.ts › findMoments, which keeps runs at least 2.5 spreads above rest for half a second or more. src/screens/review.ts › select jumps the player to three seconds before the pin.

To change this, start here

  • Too many or too few pins: THRESHOLD, MIN_SECONDS, MERGE_SECONDS at the top of src/moments.ts; the tests in test/moments.test.ts show what each does.
  • What counts as frustration or delight: the weights in src/signals.ts › rawSignals.
  • Calibration length: CALIBRATION_SECONDS in src/screens/record.ts.
  • Reel clip length and title cards: REEL_BEFORE, REEL_AFTER and card() in src/export.ts.
  • Colours and type: the variables at the top of src/styles.css.

A practice to reuse

Test the riskiest piece first, with a throwaway probe

Before the spec was written, a ten-minute probe ran the face model, a fake screen share and a recorder in headless Chromium. A second probe moved the model into a worker. That changed the design (devpost/checklist.md › Revisions, first bullet): native recorders plus a worker, because a page that draws its own video freezes when the game window covers it. On the next project, write the smallest script that proves the unfamiliar API does what the plan assumes, before planning around it.

Run it again

npm install, then npm run dev, and open http://localhost:5173 in Chrome. Tests: npm test and npm run e2e.
